# ARNIX MediaCenter

Android-приложение на Kotlin + Jetpack Compose для смартфонов, планшетов и Android TV.

## Что есть в проекте

- Нативный интерфейс ARNIX без отображения сайта Lampa.
- Каталог фильмов и сериалов, карточки и поиск через TMDB.
- Избранное, подробная информация о фильмах и сериалах.
- Нативный экран источников, который подключается к ARNIX backend.
- Встроенный Media3/ExoPlayer для прямых поддерживаемых HLS, DASH и MP4 потоков.
- Адаптивная компоновка для сенсорного управления и Android TV D-pad.

## Сборка APK через GitHub Actions

1. Откройте вкладку **Actions** репозитория.
2. Выберите **Android APK Build**.
3. Дождитесь успешного завершения workflow.
4. Откройте Artifacts и скачайте `arnix-mediacenter-debug-apk`.

APK находится внутри ZIP-артефакта. Локальная сборка: JDK 17, Android SDK и Gradle 8.9:

```bash
gradle --no-daemon assembleDebug
```

## Backend и источники

Backend находится в каталоге `backend`. Он предоставляет:

- `GET /health` — состояние сервиса и число настроенных источников.
- `GET /api/lampa/sources` — список источников, подключённых на сервере.
- `GET /api/lampa/search?q=...` — поиск по подключённым источникам.

В Android откройте **Плагины / Источники**, укажите HTTPS-адрес backend и нажмите «Сохранить и проверить».

### Настройка адаптеров

Задайте переменную окружения `ARNIX_LAMPA_ADAPTERS` на backend. Это JSON-массив объектов с полями `id`, `name` и `search_url`. URL должен использовать HTTPS и содержать буквальный маркер `{query}`, который сервер заменит URL-кодированным поисковым запросом.

Пример структуры (адрес демонстрационный, замените на свой API):
```json
[
  {
    "id": "catalog",
    "name": "Мой каталог",
    "search_url": "https://media.example/api/search?q={query}"
  }
]
```

Адаптер должен возвращать JSON-массив результатов или объект с массивом `results`. Элементы могут содержать `id`, `title`, `original_title`, `year`, `poster` и `description`. Для воспроизведения адаптер должен дополнительно вернуть `stream_url` (прямой HTTPS URL на HLS/DASH/MP4) и при необходимости `stream_type`. Только такой прямой URL попадёт в нативный экран воспроизведения. Сервер нормализует эти поля для нативного интерфейса.

### Оригинальный Lampa Runtime

В меню приложения добавлен отдельный раздел **Lampa Runtime**. Он открывает HTTPS-экземпляр Lampa, адрес которого вы указываете сами. Внутри него работает загруженная веб-среда, а не самодельная копия `window.Lampa`. Встроить оригинальные исходники Lampa непосредственно в APK этим изменением не удалось: в репозитории пока нет проверенной локальной сборки runtime и подтверждённого разрешения на её распространение.

Хост ограничивает URL стартовой страницей HTTPS-хостом, отключает доступ к локальным файлам и запрещает mixed content. Для обмена сообщениями предусмотрен переход через пользовательскую схему `arnix://bridge` (без универсального `addJavascriptInterface`). Пример вызова со стороны плагина/интеграционного кода:

```javascript
window.ArnixNative?.postMessage({
  type: "ready",
  plugin: "my-plugin",
  payload: { version: 1 }
});
```

Поддерживаемые типы сообщений на текущем этапе: `ready`, `search`, `play`, `catalog`, `error`. Экран принимает и показывает события, но обработчики действий поиска/воспроизведения ещё не связаны с соответствующими нативными сценариями. Поэтому это **первый защищённый host/bridge слой, а не завершённая полная совместимость**. Обычные плагины, использующие стандартные API Lampa, могут выполняться внутри загруженного настоящего runtime; их интерфейсы остаются веб-интерфейсами и автоматически не становятся Compose-экранами.

Для полноценной поставки офлайн-движка нужен конкретный официальный runtime source/release, проверка лицензии и его сборочных зависимостей, затем включение его файлов в APK и тестирование каждого API-плагина. Не устанавливайте неизвестные плагины: они выполняются в общей веб-среде и могут читать данные этой среды.

**Потоки:** реальных провайдеров видео в проекте пока не настроено. Backend принимает JSON-адаптеры; для воспроизведения они должны возвращать прямой HTTPS URL разрешённого HLS/DASH/MP4 потока. DRM, платные подписки и геоограничения не обходятся. TMDB ID или название сами по себе не являются ссылкой на видео.

## Примечание о каталогах и видео

TMDB используется для метаданных и постеров, а не как видеохостинг. Наличие фильма в каталоге не означает, что для него найден видеопоток. Для просмотра нужны источники, права и корректные прямые URL, поддерживаемые Media3.
